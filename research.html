World Models Self-Supervised Learning

1. JEPA: Joint-Embedding Predictive Architecture (I-JEPA & V-JEPA)

In one line

Proposed by Yann LeCun, JEPA learns a World Model by predicting the abstract embedding of a missing image patch or future video frame ($\hat{s}_y$) from the visible context ($s_x$)—instead of wasting capacity trying to predict every blade of grass or pixel texture ($y$).

Think of it like this

If a car drives behind a bus, you can easily predict the high-level concept: "in 2 seconds, the car will emerge on the left side at the same speed." You cannot predict the exact reflection on every raindrop on its windshield. Generative models (like pixel autoencoders or video diffusion) force the network to guess every raindrop pixel. JEPA predicts in representation space, where unpredictable pixel noise is filtered out and only high-level meaning remains.

How I-JEPA (Images) & V-JEPA (Video) Work Step by Step

  1. Mask large semantic blocks. Take an image (I-JEPA) or video clip (V-JEPA) and mask out large contiguous regions $y$ (e.g., an entire object or future frames), leaving visible context $x$.
  2. Encode visible context ($s_x$). Pass only the visible patches $x$ through the Context Encoder $f_\theta$ to get context representations $s_x$.
  3. Encode masked targets ($s_y$) with EMA. Pass the hidden target patches $y$ through the Target Encoder $f_{\bar{\theta}}$ (whose weights $\bar{\theta}$ are a slow moving average of $\theta$, with gradients turned off) to get target representations $s_y$.
  4. Predict in latent space. Give the lightweight Predictor $g_\phi$ both $s_x$ and positional mask tokens $z$ (telling it where in space/time to predict) to output $\hat{s}_y = g_\phi(s_x, z)$.
  5. Minimize representation distance. Train $\theta$ and $\phi$ to minimize $\|\hat{s}_y - \operatorname{sg}(s_y)\|_2^2$, then update $\bar{\theta} \leftarrow \tau \bar{\theta} + (1-\tau)\theta$.
$$\boxed{\mathcal{L}_{\text{JEPA}}(\theta, \phi) = \Big\| g_\phi\big(f_\theta(x),\, z\big) - \operatorname{sg}\big(f_{\bar{\theta}}(y)\big) \Big\|_2^2}$$

In words: $\operatorname{sg}(\cdot)$ means stop-gradient. Why is stop-gradient + EMA needed? Without it, both encoders would cheat by outputting a constant vector $\mathbf{0}$ for every image (giving $0$ loss without learning anything!).

Hands-On Code PyTorch JEPA Step

2. Step-by-Step Code: Minimal JEPA Training Step in PyTorch

jepa_training_step.py Python 
import copy
import torch
import torch.nn as nn
import torch.nn.functional as F

# 1. Context Encoder, EMA Target Encoder (cloned, no gradients), and Predictor
context_encoder = nn.Sequential(nn.Linear(64, 128), nn.GELU(), nn.Linear(128, 128))
target_encoder = copy.deepcopy(context_encoder).requires_grad_(False)
predictor = nn.Sequential(nn.Linear(128 + 16, 128), nn.GELU(), nn.Linear(128, 128))

optimizer = torch.optim.AdamW(
    list(context_encoder.parameters()) + list(predictor.parameters()), lr=1e-3
)

# 2. Simulated visible patch (x), masked target patch (y), and mask position token (z)
x_visible = torch.randn(32, 64)
y_masked = torch.randn(32, 64)
z_pos_token = torch.randn(32, 16)

# 3. Forward pass in Representation Space (no pixel reconstruction!)
s_x = context_encoder(x_visible)
s_y_hat = predictor(torch.cat([s_x, z_pos_token], dim=-1))

with torch.no_grad():               # Stop-gradient on Target Encoder
    s_y_target = target_encoder(y_masked)

# 4. L2 loss in embedding space + Backprop
loss = F.mse_loss(s_y_hat, s_y_target)
optimizer.zero_grad()
loss.backward()
optimizer.step()

# 5. EMA update of Target Encoder weights (tau = 0.996)
tau = 0.996
with torch.no_grad():
    for p_ctx, p_tgt in zip(context_encoder.parameters(), target_encoder.parameters()):
        p_tgt.data.mul_(tau).add_(p_ctx.data, alpha=1.0 - tau)

print(f"JEPA Representation Loss: {loss.item():.4f}")

What to notice: Look at lines 24–38: `target_encoder` never receives gradients from `loss.backward()`. Instead, it smoothly tracks `context_encoder` via the Exponential Moving Average (`tau = 0.996`), preventing representation collapse.

Sequence Architecture O(L) Linear Scaling

3. Mamba & Selective State Space Models (SSMs)

In one line

Standard Transformers compare every token against every other token ($O(L^2)$ quadratic cost), whereas Mamba (Selective SSM) compresses history into a fixed-size state $h_t$ using input-dependent gates—achieving $O(L)$ linear scaling and $5\times$ faster long-context inference.

$$\boxed{h_t = \bar{\mathbf{A}}(x_t)\, h_{t-1} + \bar{\mathbf{B}}(x_t)\, x_t, \qquad y_t = \mathbf{C}(x_t)\, h_t}$$
Sparse Scaling Top-K Routing

4. Sparse Mixture of Experts (MoE)

In one line

Instead of running every token through one giant FNN layer, a Mixture of Experts (MoE) layer splits the FNN into $N$ specialized experts (e.g. 8 or 64) and uses a lightweight Router to send each token to only the Top-$K$ (usually 2) experts.

5. Test-Time Compute & Flow Matching

  • Test-Time Compute (Reasoning Models): Instead of emitting an immediate answer, reasoning models generate an internal chain of thought—exploring hypotheses, checking intermediate math, and backtracking before producing the final response. Spending more compute at inference time on hard math/coding problems often beats scaling pre-training size by $10\times$.
  • Flow Matching & Diffusion Transformers (DiT): Modern image/video generators replace curved multi-step diffusion schedules with Rectified Flow Matching—training a Transformer to predict a straight-line velocity vector from pure Gaussian noise $\epsilon$ directly to clean data $x_1$ in just a few steps.
