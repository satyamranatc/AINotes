Pillar 1: LLM Autoregressive Decoding

1. How LLMs Generate Text (Autoregressive Loop)

In one line

An LLM (Large Language Model) predicts one token at a time: it scores every token in its vocabulary, picks one using Temperature and Top-$P$, appends that token to the prompt, and repeats.

  1. Tokenize the prompt. Convert input text into integer token IDs.
  2. Compute Logits ($\mathbf{z}$). Pass the token IDs through the Transformer layers to get a raw score for every possible next token.
  3. Scale by Temperature ($T$) & Softmax. Divide logits by $T$ and convert them into probabilities that add up to $1.0$.
  4. Sample & Append. Pick the next token $w_t$, tack it onto the end of the input, and loop until the stop token <eos> appears.
$$\boxed{P(w_t \mid w_{1:t-1}) = \operatorname{softmax}\left(\frac{\mathbf{z}_t}{T}\right)}$$

In words: when Temperature $T \to 0$, the highest-scoring token wins $100\%$ of the time (deterministic, ideal for code and math). When $T \ge 0.8$, probabilities flatten out so creative alternative words get picked.

2. Step-by-Step: Calling Google Gemini & Groq APIs

Example 2A: Google Gemini (`google-genai`)

call_gemini.py Python 
import os
from google import genai
from google.genai import types

# 1. Create client (reads GEMINI_API_KEY from environment)
client = genai.Client(api_key=os.environ.get("GEMINI_API_KEY"))

# 2. Call gemini-2.5-flash with a system instruction & low temperature
response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="Explain a vector database in two simple sentences.",
    config=types.GenerateContentConfig(
        system_instruction="You are a concise AI engineering tutor.",
        temperature=0.2,
        max_output_tokens=200,
    ),
)
print(response.text)

Example 2B: Groq LPU Streaming (`groq`)

call_groq_stream.py Python 
import os
from groq import Groq

# 1. Create Groq client (reads GROQ_API_KEY from environment)
client = Groq(api_key=os.environ.get("GROQ_API_KEY"))

# 2. Stream tokens as they arrive so the UI feels instant
stream = client.chat.completions.create(
    model="llama-3.3-70b-versatile",
    messages=[
        {"role": "system", "content": "You are a concise systems engineer."},
        {"role": "user", "content": "Why do we stream LLM responses?"}
    ],
    temperature=0.2,
    stream=True,
)
for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="", flush=True)

What to notice: Both SDKs take the same three core inputs: the model name, the system + user messages, and the temperature.

Pillar 2: Vector Storage Embeddings & HNSW

4. Vector Storage: How Vector Databases Index Meaning

In one line

Vector Storage (like ChromaDB, FAISS, Pinecone, or pgvector) stores document chunks alongside their dense embedding vectors so you can find the Top-$K$ most relevant passages in milliseconds using Approximate Nearest Neighbor (HNSW) search.

Think of it like this

A normal SQL database looks up exact words (`WHERE text LIKE '%refund%'`) and misses documents that say "money-back guarantee". A Vector Database arranges passages on a map by topic meaning—so searching for "How do I get my money back?" lands right next to the "30-day return & reimbursement policy" chunk.

How Vector Storage Works Step by Step

  1. Chunk your documents. Split long PDFs or docs into overlapping 300–500 token passages so each vector represents one focused idea.
  2. Embed each chunk. Pass every chunk through an Embedding Model (e.g., `text-embedding-004` or `all-MiniLM-L6-v2`) to get a normalized float vector $\mathbf{v} \in \mathbb{R}^d$.
  3. Build an HNSW graph index. Instead of brute-force KNN ($O(N)$), the vector database links vectors into a multi-layer expressway graph called HNSW (Hierarchical Navigable Small World) for $O(\log N)$ lookup.
  4. Query Top-$K$ with Metadata Filters. Embed the user's question $\mathbf{q}$, filter by metadata (e.g. `department == "HR"`), and return the $K$ closest chunks by Cosine Similarity.

Step-by-Step Code: Vector Storage with ChromaDB

terminal Bash 
pip install chromadb
vector_storage_chromadb.py Python 
import chromadb

# 1. Create an in-memory (or persistent disk) Vector Database client
client = chromadb.Client()
collection = client.create_collection(name="company_handbook")

# 2. Insert text chunks + metadata (Chroma embeds them automatically)
collection.add(
    ids=["policy_1", "policy_2", "policy_3"],
    documents=[
        "Customers can request a full refund within 30 days of purchase.",
        "Employees receive 24 days of paid annual leave per calendar year.",
        "Production database deploys require two senior engineer approvals."
    ],
    metadatas=[{"topic": "billing"}, {"topic": "hr"}, {"topic": "eng"}]
)

# 3. Semantic search: query by meaning, not exact keywords!
results = collection.query(
    query_texts=["How do I get my money back?"],
    n_results=1
)
print("Matched Chunk:", results["documents"][0][0])

What to notice: Even though the query "How do I get my money back?" shares zero words with "request a full refund within 30 days", Vector Storage retrieves `policy_1` as the #1 match.

Pillar 3: RAG Grounded Generation

5. Retrieval-Augmented Generation (RAG)

In one line

RAG (Retrieval-Augmented Generation) stops LLM hallucinations on private or up-to-date facts by retrieving relevant chunks from Vector Storage first and pasting them directly into the LLM prompt as an open-book reference.

Think of it like this

Asking a raw LLM about your company's internal codebase is like giving a smart student a closed-book exam on a book they have never seen—they will guess (hallucinate). RAG turns it into an open-book exam: first look up the exact page in the Vector Database, hand that page to the LLM, and say "Answer using only this page."

Step-by-Step Code: End-to-End RAG in 30 Lines

rag_end_to_end.py Python 
import chromadb
from groq import Groq

# 1. Index knowledge chunks into Vector Storage
vdb = chromadb.Client().create_collection("docs")
vdb.add(
    ids=["c1", "c2"],
    documents=[
        "Project Atlas launches on November 15 with a budget of USD 120,000.",
        "Support tickets with Severity-1 must be acknowledged within 15 minutes."
    ]
)

def answer_with_rag(question: str) -> str:
    # 2. Retrieve Top-2 relevant chunks from Vector Storage
    hits = vdb.query(query_texts=[question], n_results=2)
    context = "\n".join(hits["documents"][0])

    # 3. Build grounded prompt and call the LLM
    prompt = f"Use ONLY the context below to answer.\nContext:\n{context}\n\nQuestion: {question}"
    res = Groq().chat.completions.create(
        model="llama-3.3-70b-versatile",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.0,
    )
    return res.choices[0].message.content

print(answer_with_rag("When does Project Atlas launch and what is its budget?"))

What to notice: Setting `temperature=0.0` and instructing the model to "Use ONLY the context below" keeps answers strictly faithful to retrieved facts.
